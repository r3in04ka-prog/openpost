# Как готовить релиз OpenPost

Это памятка сопровождающему проекта. Изменение документации само по себе не требует новой версии приложения.

1. Проверьте изменения и обновите номер версии в pyproject.toml и installer/openpost.iss.
2. Обновите CHANGELOG.md: пользовательское поведение, исправления и ограничения.
3. Выполните проверки из CONTRIBUTING.md. Проверьте интерфейс с демонстрационными данными.
4. Создайте тег vX.Y.Z после проверок: Windows installer workflow соберёт установщик и контрольную сумму. При новой версии сначала обновите фиксированное имя установщика в workflow.
5. Убедитесь, что установщик запускается, версия соответствует тегу и SHA256SUMS.txt вычислен для именно этого файла.
6. Опубликуйте релиз. Назовите файл скачивания явно; не подменяйте опубликованные файлы другим бинарником с тем же именем.
7. Проверьте ссылку скачивания и инструкцию обновления. Для тестовой версии включите отметку pre-release.

## Шаблон описания релиза

### Что нового

Два-три конкретных изменения для пользователя.

### Скачать

Укажите точное имя установщика Windows x64 и файл SHA256SUMS.txt. Если прикладываете исходники отдельно, поясните, что они не являются установщиком.

### Как начать

Установить → открыть приложение → «Демо». Для своей почты указать IMAP/SMTP и пароль приложения.

### Ограничения и обновление

Перечислите существенные ограничения текущей версии, наличие цифровой подписи и порядок обновления. Не заявляйте непроверенные функции как готовые.
