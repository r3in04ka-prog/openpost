# Участие в OpenPost

Начать можно с документации, проверки деморежима, доступности интерфейса или небольшой задачи из [ROADMAP.md](ROADMAP.md). Для заметной функции сначала откройте [issue с идеей](https://github.com/r3in04ka-prog/openpost/issues/new/choose), чтобы согласовать сценарий и границы изменения.

## Запуск

Нужен Python 3.11+ с Tcl/Tk. В Windows установите Python с компонентом Tkinter; в Linux может потребоваться python3-tk.

```sh
git clone https://github.com/r3in04ka-prog/openpost.git
cd openpost
python -m venv .venv
```

Активируйте окружение (`.venv\Scripts\activate` в Windows или `source .venv/bin/activate` в macOS/Linux), затем:

```sh
python -m pip install -e .
python -m openpost
```

Для проверки без почты нажмите «Демо» или выполните `python tests/launch_demo.py`.

## Проверки

```sh
python -m unittest discover -s tests -v
python -m compileall -q openpost tests
python -m tests.gui_smoke
```

Последняя проверка открывает настоящие виджеты и требует графической среды. Обычные тесты используют имитацию серверов. Проверка отправки с реальной почтой не является обязательным условием для вклада: не публикуйте письма и пароли в issues.

## Первый pull request

1. Сделайте fork и создайте отдельную ветку для одной задачи.
2. Внесите небольшое изменение. Поведение существующих функций сохраните, если его изменение не является целью задачи.
3. Проверьте затронутые сценарии. Для сетевой логики используйте имитацию серверов; для интерфейса — демонстрационные данные.
4. Откройте pull request: проблема, новое поведение и как оно проверено. Для интерфейса приложите снимок только окна приложения.

Не добавляйте сборки, окружение, секреты или частные данные. Внешние изображения реальных писем не должны загружаться автоматически; проверка TLS и безопасная работа с почтовыми серверами должны сохраняться.

## Релизы

Установщик собирается workflow Windows installer. Порядок выпуска описан в [RELEASING.md](RELEASING.md). Публикацию версии и проверку установщика выполняет сопровождающий.
